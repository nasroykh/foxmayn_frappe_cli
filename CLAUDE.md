# CLAUDE.md — Project Context for AI Agents

## Project

**ffc** (Foxmayn Frappe CLI) — A Go CLI for interacting with Frappe ERP sites via the REST API.

## Tech Stack

- **Language:** Go 1.26 (toolchain go1.27.1)
- **CLI framework:** [cobra](https://github.com/spf13/cobra)
- **Config:** [go.yaml.in/yaml/v3](https://github.com/yaml/go-yaml) (read as structs, edited as `yaml.Node` trees) + env vars
- **HTTP client:** [resty](https://github.com/go-resty/resty)
- **Table & styling:** [lipgloss v2](https://charm.land/lipgloss/v2) + built-in `table` sub-package
- **Forms & prompts:** [huh](https://github.com/charmbracelet/huh)
- **Spinner:** [huh/spinner](https://github.com/charmbracelet/huh) (standalone, no bubbletea loop needed)
- **MCP server:** [mark3labs/mcp-go](https://github.com/mark3labs/mcp-go) v1.1.1 (stdio + StreamableHTTP transports)
- **JSONC editing:** [tailscale/hujson](https://github.com/tailscale/hujson) (pseudo-version; `ffc mcp install` edits client configs as a syntax tree)

## Build & Run

```bash
make build          # Compile binary to ./bin/ffc
make install        # Install to $GOPATH/bin + set up config
make tidy           # go mod tidy
make vet            # go vet ./...
make fmt            # gofmt -w .
make test           # go test -race ./...
make lint           # gofmt check, go vet, staticcheck (pinned, via go run)
make vuln           # govulncheck (pinned, via go run)
make clean          # Remove binary
```

Version info is injected at build time via ldflags (see Makefile).

## Release

Releases are automated via GoReleaser + GitHub Actions (`.github/workflows/release.yml`).

To cut a release:

```bash
git tag v0.1.0
git push origin v0.1.0
```

GitHub Actions will cross-compile for linux/darwin/windows × amd64/arm64, create a GitHub Release, upload the tarballs, and generate `checksums.txt` and its Ed25519 signature `checksums.txt.sig`.

**Release signing.** GoReleaser's `signs` step runs `go run ./tools/relsign sign` with the `FFC_RELEASE_SIGNING_KEY` repository secret (base64 Ed25519 seed). `ffc update` verifies the signature against `internal/relsig/keys.go` and refuses a release without a valid one. relsign refuses a secret that does not match `ReleaseKeys`, and `TestReleaseKeysConfigured` fails while `ReleaseKeys` is empty. To rotate: generate a key with `go run ./tools/relsign keygen <file>`, add its public key to `ReleaseKeys` (and `RELEASE_KEYS` in install.sh) next to the old one, ship a release signed with the old key, then switch the secret. Never commit a private key.

**Backup key.** `ReleaseKeys` also holds an offline backup key (second entry) whose private half is not in CI. If the CI key is lost or leaked, switch `FFC_RELEASE_SIGNING_KEY` to the backup key (released binaries since v1.6.3 already trust it), remove the compromised key from `ReleaseKeys` and install.sh in that release, and generate a new offline backup.

**Desktop release.** Tag `desktop-vX.Y.Z` (not `v*`, so release.yml and GoReleaser ignore it) after writing `desktop/release-notes/X.Y.Z.md` (a default unsigned-beta text is used when it is missing). It is always `--latest=false` (install scripts and ffc <= v1.11.0 read releases/latest), and a prerelease for 0.x or a `-` suffix.
Builds are unsigned until the secrets exist (APPLE_CERTIFICATE_P12_BASE64, APPLE_CERTIFICATE_PASSWORD, APPLE_ID, APPLE_TEAM_ID, APPLE_APP_PASSWORD; WINDOWS_CERTIFICATE_PFX_BASE64, WINDOWS_CERTIFICATE_PASSWORD); those signing steps have never run.

End users install with:

```bash
# Linux / macOS
curl -fsSL https://raw.githubusercontent.com/nasroykh/foxmayn_frappe_cli/main/install.sh | sh

# Windows (PowerShell or cmd.exe)
powershell -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/nasroykh/foxmayn_frappe_cli/main/install.ps1 | iex"
```

**Key files:**
- `.goreleaser.yaml` — build matrix, archive naming, checksum config
- `.github/workflows/release.yml` — triggers on `v*` tags; runs `go mod tidy -diff`, vet and tests, then GoReleaser and a build-provenance attestation. Actions are pinned to commit SHAs.
- `.github/workflows/ci.yml` — gofmt, tidy check, vet, race tests, staticcheck, govulncheck, vet and tests on windows-latest (no -race), and a cross-build on every push/PR
- `.github/workflows/desktop.yml` — desktop/ on windows-latest and macos-latest when desktop/, internal/ or go.mod change: npm ci, tsc + vite build, `go mod tidy -diff`, vet, tests, `wails3 build` (CLI version from desktop/go.mod), committed bindings and lockfile unchanged, govulncheck (macOS)
- `.github/workflows/desktop-release.yml` — `desktop-v*` tags publish; a PR touching the file or desktop/build/**, and a manual run, are dry runs (artifacts only). Windows per-user NSIS installer and universal macOS dmg (version stamped through `wails3 update build-assets` plus the `APP_VERSION` ldflags in the windows/darwin Taskfiles), then checksums.txt signed with relsign, provenance attestation and a prerelease with `--latest=false`
- `install.sh` — Linux/macOS: detects OS/arch, downloads tarball, verifies SHA256, installs to `/usr/local/bin` or `~/.local/bin`
- `install.ps1` — Windows: detects arch, downloads zip, verifies SHA256, installs to `%LOCALAPPDATA%\Programs\ffc`, adds to user PATH
- `install-desktop.sh` / `install-desktop.ps1` — the desktop app: newest `desktop-v<X.Y.Z>` from the releases API (`FFD_VERSION` overrides), SHA-256 (+ signature with OpenSSL 3 on macOS, keys kept in sync by `TestInstallScriptInSync`), then the app to `/Applications` (or `~/Applications`) via hdiutil + ditto + `codesign --verify`, or the NSIS setup run with `/S` (per user). Closes only the installed copy. A curl/PowerShell download carries no quarantine/mark of the web, so the unsigned app skips Gatekeeper and SmartScreen; that is their purpose until the app is signed. The update notice runs them from the release tag (`desktopInstallCommand`)

## Testing

- **Fake Frappe (`internal/frappetest`).** An in-memory site for unit tests: `/api/resource` CRUD with filters, fields, paging and ordering, the `/api/method` endpoints ffc calls, files (upload_file, attach_file, /files and /private/files, download_pdf, get_html_and_style; files.go), API-key/Bearer/session auth, login and logout counters, and Frappe's real error shapes (`exc_type`, `_server_messages`, `exception`, captured from a v16 site). `HandleMethod` adds a whitelisted method, `Handle("METHOD /path", h)` overrides a route (`ErrorHandler`, `HTMLPage`), and `Requests()` returns what was sent.
- **CLI harness (`internal/cmd/cli_harness_test.go`).** `fakeConfig(t, site, "apikey"|"password"|"oauth")` writes a config; `runFFC(t, cfg, stdin, args...)` runs the root command with stdout/stderr captured and resets every flag afterwards.
- **MCP.** `newMCPFake(t, readOnly)` registers the tools against a fake site; `callTool` goes through JSON-RPC so argument decoding matches a real client.
- **Contract tests (`internal/cmd/contract_test.go`, build tag `contract`).** Run against a real, disposable site: `make contract SITE=<ffc config site>`, or `FFC_CONTRACT_URL` with `FFC_CONTRACT_API_KEY`/`_SECRET` or `FFC_CONTRACT_USER`/`_PASSWORD`. Each run creates the custom submittable DocType `FFC Contract Test` (child `FFC Contract Test Item`, a Custom Field and a Property Setter), and removes it again, leftovers of an interrupted run included. They pin number literals (Currency always `x.0`), the list default (`name` only), child-table PUT (replaces rows), submit/cancel/amend (`frappe.client.submit` takes the doc, an amendment is `<name>-1`, editing a submitted doc is UpdateAfterSubmitError 417), schema merging, session logout and POST without CSRF, and that the fake fails like the real site. `.github/workflows/contract.yml` runs them nightly against ERPNext v15 and v16 from frappe_docker's pwd.yml.
- Every new command or tool ships with tests against the fake. Behaviour the fake cannot prove (real Frappe semantics) belongs in the contract tests (T1.7 layer 2).

## Conventions

- **Error handling:** Wrap with `fmt.Errorf("context: %w", err)`. Never log and return; return and let caller decide.
- **Stdout vs stderr:** Data goes to stdout, diagnostics/errors go to stderr.
- **Exit codes (`exit.go`, part of the CLI contract; docs/cli/exit-codes.md):** 0 ok, 1 generic (also a failed `ffc doctor` check, via `codeError`), 2 usage, 3 auth, 4 not found, 5 permission, 6 validation/conflict, 7 network/server, 8 partial bulk, 130 interrupted. `ffc can` answering "denied" is `deniedError` (5, the result is still printed). `classify` maps typed errors: `client.APIError` (status + exc_type), `client.AuthError` (login), `client.TransportError` (no response), `client.StateError` (document in the wrong state, 6), `usageError` (`usageErrorf` for invalid flag values; anything cobra rejects before RunE is wrapped automatically), `partialError` (bulk). Return these types instead of plain errors where the class matters. With `--json`, `reportError` prints `{"error":{code,exit_code,status,exc_type,message}}` on stderr. Only the config TUI's explicit "Cancel" exits 0.
- **No prompts without a terminal.** `runForm` returns `errNoInput` (a usage error) when `--no-input` is set or stdin is not a TTY; `confirm` turns it into "pass --yes". New prompts must go through `runForm`.
- **Environment:** `applyEnv` (cobra.OnInitialize) fills `--site/--config/--timeout` from `FFC_SITE/FFC_CONFIG/FFC_TIMEOUT` when the flag is unset; an invalid value fails in the RunE wrapper (`trackRunStart`).
- **Config precedence:** flags > env vars > config file > defaults.
- **Auth:** Bearer token for OAuth sites; `Authorization: token key:secret` for API-key sites; `Cookie: sid=<sid>` for username/password sites. `client.New()` picks the method from `cfg.AccessToken` / `cfg.APIKey`+`cfg.APISecret` / `cfg.IsSessionAuth()`, in that order. `client.New()` is fallible because session sites log in inside it.
- **Adding a data command:** create `internal/cmd/<name>.go`, set `Args: cobra.NoArgs`, call `callSite(cmd, title, func(ctx, c) ...)`, register via `rootCmd.AddCommand()` in `init()`. Print the result with `render(v, fields, tableFn)` (or `if machineOutput() { return printResult(v) }` before the table code), never `output.PrintJSON` directly, so `--output`/`--jq` work. Lists use `listDocs` for `--all`. JSON-valued flags go through `parseObject`/`filtersFlag`/`jsonFlag` so `@FILE`/`@-` work. Never build a client with `client.New` directly in a command — use `newClient`/`callSite` so OAuth refresh happens. A command that writes registers `--dry-run` with `addDryRun` and skips its confirmation when `dryRunOn(cmd)`.
- **Adding an MCP tool:** use `toolHandler(env, parse)`; read JSON-valued params with `jsonArg`/`rawJSONArg`/`objectArg` (never `req.GetString` — it returns "" for a native object), integers with `intArg`. Add the tool to `toolActions` in mcp_policy.go (read, write or method; its read-only annotation must match, `TestMCPPolicyCoversEveryTool` checks both) and to `toolSurface` (tool set, title, `big`; `TestMCPToolSurface`), and teach `scopeOf` any argument that names DocTypes or documents. registerTools drops the tools the policy (read_only, allow_tools) does not allow.

## Config

Default config path: `~/.config/ffc/config.yaml` (dir 0700, file 0600, lock file `config.yaml.lock`).

Env vars:
- `FFC_API_KEY` + `FFC_API_SECRET` — only honoured as a pair; they then replace every stored credential of the selected site.
- `FFC_URL` — applies only together with that pair (never redirects stored credentials to another host); `FFC_URL` alone that differs from the site URL is an error, so a script aimed at another host never runs against the stored one. With no config file at the default path, the three env vars alone define the site.
- `FFC_NO_UPDATE_CHECK=1` — disables the background update check.
- `FFC_OAUTH_CLIENT_SECRET` — secret of the OAuth Client given with `--client-id` (setup only, `setupFlags.oauthClient`; stored as `oauth_client_secret`); ignored with a warning without `--client-id`.

## Common Pitfalls

- The `config.yaml` in the project root is gitignored — it's for local dev only. Do not commit credentials.
- **All config writes go through `config.Edit` (or `config.Overwrite` for a fresh file).** They take `config.yaml.lock`, re-read the file, apply the callback to a `config.File` (yaml.Node tree: keeps comments and key order), and write atomically at 0600, following symlinks. Return `config.ErrUnchanged` from the callback to skip the write. Any network call made while holding the lock must be bounded by `config.MaxLockHold` (30 s; the lock is considered stale after 3×), and release removes the lock only if it still holds this process's token. Never write config.yaml with `os.WriteFile` or by marshalling the struct.
- Site names keep their case and may contain dots (`Prod`, `erp.example.com`). `--site`/`default_site` match exactly first, then fall back to a unique case-insensitive match (what viper users relied on). viper was removed because it lowercased keys and split them on dots; do not reintroduce it. `Config`/`SiteConfig` carry `yaml` tags only.
- Response JSON is decoded with `UseNumber`, so numbers arrive as `json.Number` (exact large ints, `0.0` stays `0.0` in `--json`). Code that inspects a numeric value must handle `json.Number` (see `numeric` in get_schema.go); `output.formatValue` prints integer literals as-is and formats the rest with the number format. Trailing data after the JSON body is an error.
- Frappe API wraps list results in `"data"` (v14+) or `"message"` (older). The client handles both. A 2xx single-document response without `data` is an error, not an empty doc.
- Reading, creating or updating a document of a DocType that does not exist is a 500 `ImportError` ("No module named 'frappe.core.doctype.x'"), not a 404; GetDoc/CreateDoc/UpdateDoc then probe the DocType's list (`missingDocType`; a 404 there means no DocType record), set `APIError.MissingDocType`, and `classify` makes it not found (exit 4). The message cannot be trusted: sites that hide tracebacks send none. Listing and deleting give a real 404. The fake and the contract tests pin both.
- Frappe error responses contain nested JSON strings with Python tracebacks. `frappeErrorResponse.userMessage()` extracts the user-facing message; non-JSON error bodies are cut to 300 runes and sanitised.
- **Redirects:** only GET/HEAD follow redirects. A redirected POST/PUT/DELETE fails with the target URL, because Go would otherwise replay it as a body-less GET and report success (e.g. delete-doc against an `http://` URL that redirects to `https://`). A followed redirect never goes from https to http, and a request carrying `Authorization` or `Cookie` is never redirected to another host name (Go would copy them to a subdomain); both fail with a `*client.RedirectError`.
- Non-site HTTP (GitHub release API, downloads) uses `client.NewHTTPClient(timeout)`, never `resty.New()` — resty's default logger prints `WARN RESTY` lines on stderr.
- **Retries:** only GET, on 429/502/503/504 and on transport errors, never after a timeout or cancel, a refused redirect or a TLS/certificate error (`retryableTransport`). A Retry-After up to 10 s (`maxRetryAfter`) is honoured; a longer one is reported instead of retried. Do not add retries to writes.
- **OAuth refresh** happens in `loadSite` (site_client.go), only for commands that talk to a site, under the config lock; it re-checks expiry after taking the lock so concurrent processes refresh once. Failures warn on stderr and the command proceeds (it then gets a 401). There is no refresh in `PersistentPreRunE` any more. **During a run** (T2.11), `newSiteClient` gives an OAuth client `tokenRefresher` (refreshOAuth with the rejected token: the stored token is taken when it differs, so a refresh by another process is reused). The access token is attached per request in `client.send`, not on the resty client. On a 401, `refreshToken` (single-flight under `loginSem`, a one-slot channel a waiter leaves when its ctx ends; keyed by the token the request used) first probes `frappe.auth.get_logged_user` with that token: only a 401 there means the token itself is refused (Frappe checks it in `validate_auth`, frappe/auth.py, before the method runs), so the request did not run and is repeated once, writes and `Raw` included (`Raw` bodies are `[]byte`, replayable). A 401 the method raised itself (token still valid) is returned, never retried; a write rejected while another request already refreshed probes its own token too (a read just retries). A failed refresh is returned as the 401 with a hint and remembered per token only when definitive (`permanentRefreshError`: token endpoint 400/401/403 (403 is Frappe's answer to a revoked refresh token), `ErrNoRefreshToken`, a refreshed token refused again by `refreshedRefused`, e.g. a disabled user); 5xx, network and lock errors are retried by the next request. The MCP server uses `newSiteClient` too; its cached client is rebuilt when the stored token changes. Fake: `ExpireToken`/`ExpireTokenAfter`, `FailRefresh`, `Refreshes`, `RefreshToken`/`OAuthClientID` (in `fakeConfig(…, "oauth")`); the real 401 and refresh are pinned by `TestContractOAuthExpiry` (contract_oauth_test.go).
- Username/password (session-cookie) auth has no `sid` in config. CLI commands log in once per invocation and log out when they finish (`callSite`, `bulkFlags.run` and `ping` defer `c.CloseQuietly()`, which POSTs `/api/method/logout` with a fresh 5 s context); without that, every run left a live session in the `Sessions` table. A command that builds its own client must do the same. Long-lived users of one client (MCP daemon, bulk runs) rely on `FrappeClient.relogin`: on a 401/403 with a session older than 1 minute it first asks `frappe.auth.get_logged_user` whether the session is still valid (then it is a real permission error, no new login), and logins are single-flight under `loginMu`, keyed by the sid each request used. `Close(ctx)` logs out; the MCP provider drops a replaced client without logging out (in-flight calls may still use it). Do not persist a `sid` to config.
- The plaintext `password` field in `SiteConfig` is stored at 0600 — same protection as `api_secret`. ffc has no OS-keychain integration.
- In huh v1.0.0, only `ctrl+c` is bound to Quit by default. Use `runForm` (auth_wizard.go), which adds Escape via `escQuitKeyMap()` and maps an abort to `errAborted`.
- `update_check.go` sets `rootCmd.PersistentPreRunE` in its `init()`. Do not set it anywhere else — it would silently overwrite the hook.
- The update check is skipped for `update`, `mcp` (and subcommands), `completion`, `__complete` and `help`, and when `FFC_NO_UPDATE_CHECK` is set. `checked_at` is recorded before the fetch, so a failing network costs at most one attempt per day. State file: `~/.config/ffc/.update_check.json` (0600).
- OAuth PKCE: the callback server binds `127.0.0.1` (the redirect URI is `http://127.0.0.1:<port>/callback`, not `localhost`) before the form opens, accepts exactly one result, answers duplicates with 409, and is always closed on abort.
- **OAuth registration and revocation (T3.7).** Frappe facts (v16.36.1 source; v15 branch checked on GitHub): the metadata is `GET /.well-known/oauth-authorization-server` (app.py:172 → `handle_wellknown`, oauth2.py:293), served only while OAuth Settings `show_auth_server_metadata` is set (default 1, oauth_settings.json), else NotFound; it carries `registration_endpoint` only while `enable_dynamic_client_registration` is set (default 1; oauth2.py:353). v15 has neither (no `handle_wellknown`, no `register_client`), so any non-200/non-JSON metadata means "no registration". `register_client` (oauth2.py:359, allow_guest POST, JSON body; NotFound when disabled) validates `OAuth2DynamicClientMetadata` (integrations/utils.py:17, pydantic: `redirect_uris` and `client_name` required) and `validate_dynamic_client_metadata` (utils.py:206: grant types ⊆ authorization_code/refresh_token, response types only `code`, outside developer mode https or an http loopback IP literal, any port; `localhost` is refused), then `create_new_oauth_client` (utils.py:241): app_name = client_name, scopes = `scope` or "all", `skip_authorization` 0 (the consent page shows), grant Authorization Code, `token_endpoint_auth_method` "None" for `none` (public, no secret in the 201 answer), owner Guest, allowed role Desk User (oauth_client.py:62; a website user cannot use it). No check for an existing client: every call creates one. v16.36.1 has no rate limit on it; Frappe's develop branch has `@rate_limit(limit=5, seconds=600)` per IP (429 RateLimitExceededError), which the hint names. Frappe stores redirect URIs joined by `\n` but `validate_redirect_uri`/`confirm_redirect_uri` split them on spaces (oauth.py:27-40, 170-179), so ffc registers exactly one URI (this run's port) and the scope `openid all` (a missing `openid` would fail `validate_scopes`, oauth.py:48). `sitesetup.ResolveOAuthApp` posts to the configured site URL with the endpoint's path (the issuer comes from the request URL, which can be http:// behind a TLS proxy) and refuses another host. `revoke_token` (oauth2.py:188, allow_guest POST, form body) runs oauthlib's RevocationEndpoint: `client_authentication_required` is not overridden (always true), so `authenticate_client` (oauth.py:93) loads the client from `client_id` in the body (no secret checked; without it, it looks up `token` as an access token name, which fails for a refresh token); the validator's `revoke_token` (oauth.py:263) sets the OAuth Bearer Token with that `refresh_token` (hint `refresh_token`) or that name (otherwise) to Revoked, which kills the access token of the same record too (a refresh with the revoked refresh token is then a 403 PermissionError, not invalid_grant: validate_refresh_token's get_doc raises DoesNotExistError, which `handle_does_not_exist_error`, permissions.py:926, turns into PermissionError for Guest; `permanentRefreshError` counts that 403 as definitive, so a long-running client stops refreshing; an unknown `client_id` is the same 403, from authenticate_client's get_doc, which revoke_token does not catch at oauth2.py:198; revoking by the access token revokes the record and so its refresh token too); the answer is `{}` with 200, also for an unknown token, or oauthlib's status (400 for a missing token: create_revocation_response catches its own InvalidRequestError). site remove therefore sends `token`, `token_type_hint=refresh_token` (access token when there is none), `client_id`, no Authorization header (an expired bearer would be refused by validate_auth first), before taking the config lock (`sitesetup.RevokeToken`), bounded by `revokeTimeout` (10 s, site.go), and only warns on failure. A refresh leaves the previous refresh token active (`save_bearer_token`, oauth.py:203, saves a new record with `new_doc` and never revokes the old one), so older refresh tokens of the same login are not revoked. Fake: `SetAuthServerMetadata`, `SetDynamicRegistration`, `FailRegistration(status)`, `Registrations()`, `Revoked()`, `AuthCode` (the token endpoint's authorization_code grant); cmd tests stub `openBrowserFn`, sitesetup tests pass `LoginHooks.OpenBrowser`. Contract: `TestContractOAuthRevoke`, `TestContractOAuthRegistration` (skips without registration).
- `IsOAuth()` returns true only if `AccessToken != ""`. `IsSessionAuth()` requires both `Username` and `Password`.
- `client.LoginPassword` does not support Frappe 2FA; it returns an error pointing to OAuth or an API key.
- `SiteConfig.Name` is a runtime-only field (`yaml:"-"`) set by `config.Load` to the exact YAML key; token writes use it as the site key.
- **`-o` is local only:** `list-docs --order-by`, and `--output-file` of `download` and `pdf`. The output format flag is `--output` with no shorthand (a persistent `-o` would panic on the shorthand clash). Never make `-o` persistent.
- `--output json` must stay byte-identical to the old `--json` (indented, HTML-escaped by encoding/json). YAML numbers go through `yamlNode` (yaml.v3 would quote a json.Number).
- **`ffc api` defaults to GET even with fields** (gh switches to POST): a bare `-f` on `/api/resource/X` would create a document. Only `--input` implies POST. `SitePath` refuses absolute and `//host` URLs; `CheckHeaders`/`Raw` refuse `Authorization`, `Cookie`, `Host`, `X-Frappe-Site-Name` and `X-Forwarded-Host` (the last three route to another site on a bench). Keep both checks in the client: they are the credential boundary.
- **MCP stdout is the JSON-RPC channel.** Tool handlers must never write to stdout or call `output.Print*`. Return results via `marshalResult`/`mcp.NewToolResultText` and errors via `mcp.NewToolResultError` with a nil Go error. Stderr is safe in stdio mode (clients log it) and is `mcp.log` in detached mode — never print secrets there (the daemon prints its bearer token only to a terminal; `ffc mcp status` shows it).
- **Identity and permissions (T2.4).** Frappe signatures (v16.36.1 source): `frappe.utils.change_log.get_versions()` (change_log.py:105, any logged-in user; `{app: {title, description, branch, color, logo, version}}`), `frappe.auth.get_logged_user()` (auth.py:451), `frappe.client.has_permission(doctype, docname, perm_type="read")` (client.py:325, returns `{"has_permission": bool}`; **docname is required**, omitting it is a 500 TypeError, so a DocType-level question cannot be asked: `DocTypePermission` applies the getdoctype `permissions` rows (permlevel 0) to the user's roles instead, `basis: "doctype"`), `frappe.client.get_doc_permissions(doctype, docname)` (client.py:336, `{"permissions": {...}}`; a document the controller refuses comes back as `{"null": 0}`, which `DocPermissions` turns into an empty set). `has_permission` is true for Administrator before the DocType or document is looked up; for others a missing document is 404 and an unknown DocType 403. `has_permission` and `get_doc_permissions` can disagree (a User may edit their own User document: true vs write 0): `has_permission` is the authoritative one. All of these are GETs, so a dry run does not hold them back. `EvalDocTypePermission` mirrors `get_role_permissions` (permissions.py:318-345): an `if_owner` row narrows a right only when no non-`if_owner` applicable row grants it and never `create` (select/read stay allowed with `owner_only`, other rights are denied with `owner_only`); `select` is implied by `read` (213); `submit`/`cancel`/`amend` need `is_submittable` and `import` `allow_import` (Frappe itself checks only submit and import; ffc also zeroes cancel/amend); a child table (`istable`) is a `client.ChildTableError` (exit 2: `has_permission` delegates to the parent, `has_child_permission`). Desk User is added only when the User doc's `user_type` is readable and is System User (it is permission level 1); otherwise `DocTypePermission.Note` says what it left out. On the `-n` path `parsePerm` accepts any lower-case identifier (custom v16 permission types); at DocType level only `client.PermTypes`. `ffc can` and `check_permission` share `checkPermission`; the MCP tool uses the argument names `doctype`/`name`, so `scopeOf` and the DocType policy apply unchanged. MCP `whoami` reads the User DocType, so `scopeOf` adds `User` to its scope (deny_doctypes/allow_doctypes for User apply); it gets its site from `siteFrom(ctx)` (`withSite`, set next to `withPolicy` in `env.run`) so it works per site with several sites. whoami and every URL printed use `redactedURL`.
- **Server version cache.** `serverInfo` caches get_versions per site for 24 h (`serverCacheTTL`) in `os.UserCacheDir()/ffc/<sanitized name>-<hash of the exact name>/<credentialID>/server.json` (dir 0700, file 0600, atomic write; a nameless env-only site is keyed by its URL). An entry is ignored when damaged, expired, dated in the future, or read from another URL; `--refresh` (whoami, doctor) skips it; a 404, 5xx or transport error from the versions call drops it (`serverChanged`). The directory comes from the package var `sitecache.UserCacheDir` (default `os.UserCacheDir`); TestMain and `cacheTEnv` (cmd) and the desktop services TestMain point it at a temp dir, so no test touches the real cache on any OS. Version-dependent behaviour calls `serverInfo(...).FrappeMajor()`; never build a cache path from a raw site name (`sitecache.DirName`). doctor does not use the cache.
- **doctor.** Check ids (`config.file`, `config.dir`, `config.parse`, `config.lock`, `net.tls`, `net.reachable`, `net.clock`, `auth.valid`, `auth.oauth_token`, `server.versions`, `server.api_v2`, `mcp.daemon`, `mcp.state_file`, `update.check`) are a JSON contract: never rename. fail makes exit 1, warn does not. It changes nothing: no lock removal, no stale MCP state cleanup (`mcpDaemonStatus` is shared with `ffc mcp status`, which does clean up), no OAuth refresh (it builds its client with `client.New` from the stored config on purpose, reports an expired token as a warning, and skips `auth.valid` then), no version cache read or write (always live; no `--refresh`), and a password site's login is closed with `CloseQuietly`. `net.reachable` and `net.tls` come from one GET of `frappe.ping` through the normal transport (proxy honoured); `resp.RawResponse.TLS` gives the certificate and a changed final URL is a failure with the final site URL as the hint. The MCP state file mode is checked whenever the file exists. Probes that need the site are skipped when `net.reachable` fails. Never print a secret: parse errors have their backtick-quoted values stripped, URLs go through `redactedURL`, the MCP token and OAuth token are never included. `ping` now also calls `get_logged_user` and exits 3 on rejected credentials or Guest, because `frappe.ping` works without login (documented behaviour change in docs/cli/sites-and-settings.md); `ffc whoami` as Guest prints its result, then exits 3 too.
- **Lifecycle:** every state change goes through Frappe's whitelisted methods (`frappe.client.submit` with the document as read, so the timestamp check applies; `frappe.client.cancel`, `rename_doc`, `frappe.model.workflow.*`, the Deleted Document `restore`). amend-doc and copy-doc build the copy client-side from GetDoc (`clean`): the v2 `/copy` route ignores its `ignore_no_copy` query parameter, so both read the meta from `frappe.desk.form.load.getdoctype` (whose data is in `docs`, not `message`; the fake returns it with `frappetest.Response`). Like the desk, a copy never carries Password fields (masked) or `lft`/`rgt` (a tree node keeping them corrupts the nested set); copy-doc also drops "no copy" fields, amend-doc keeps them and sets `amendment_date` when the DocType has it. Fake meta: `DocField`, `NoCopy`, `ChildTable` (also stamps row identity), `AllowOnSubmit`. An amendment is `<name>-1`, an amendment of `<x>-<n>` is `<x>-<n+1>`; a second amendment of the same document is a duplicate. `restore` may give a hash- or series-named document a new name (`Deleted Document.new_name`). submit-doc/cancel-doc refuse a DocType with an active Workflow (StateError); a 403 reading Workflow skips the check. `discard` exists only in v16: the missing-method error is translated, so it is detected by the method name in a 417 and wrapped with ErrNeedsV16 (exit stays 6). Workflow bulk is client-side (`bulk_workflow_approval` reports per-document failures only as msgprint).
- **`--dry-run`** is per command (`addDryRun`), not global; MCP never dry-runs. The context mark is set in the `trackRunStart` wrapper, and `client.send` returns a `*client.DryRunError` instead of sending: scope "writes" holds back everything but GET/HEAD (reads run, so state errors still surface), scope "all" (call-method, api) holds back everything. The error stops the command at its first write; `execute` prints the plan and exits 0. A new write command must call `addDryRun` and skip its confirmation when `dryRunOn(cmd)`. Login/logout use their own resty clients and still run, and so does an OAuth refresh in `loadSite` (reads need a valid token).
- **`--debug`** sets `client.Debug` in `applyEnv` (`resolveDebug`), so it applies to clients built afterwards; the spinner is off while tracing, and the detached MCP child gets `--debug=<level>`. Any new place that logs requests or plans must use the redaction helpers in debug.go; `TestDebugNeverPrintsSecrets` covers all three auth methods.
- **MCP policy (T1.4b).** `sites.<name>.mcp` (`config.MCPPolicy`, unknown keys are an error) is read on every tool call (`env.site` = `loadSiteConfig`, no network); `toolHandler` checks it before `env.client`, so a refused call sends nothing. Config may loosen the built-in rules (sensitive DocTypes, `deniedMethods`); the `ffc mcp` flags only narrow (`mcpFlags`; passed to the detached child by `daemonArgs`). `applyEnvOverrides` and `File.PutSite` keep the `mcp` block: dropping it would widen access silently. Every call writes one audit line (`auditLog.write`: args via `client.RedactArgs`, which copies, then `data`/`args` reduced to keys and size; secret argument values are also cut out of error text, list-form filters on secret fields are redacted, and every caller-controlled string is sanitised and clipped). `scopeOf` trims DocType names and refuses invisible characters; for call_method it walks the whole args tree (JSON strings included) for `doctype`/`dt`/`ref_doctype`/… and refuses a `docMethods` call that names no DocType. `allow_doctypes` from the config needs `allow_methods` from the config: a flag list never stands in for it. Query arguments (`queryScope`, mcp_query_scope.go: list_docs/count_docs/aggregate `filters`, `fields`, `order_by`, and `filters`/`or_filters`/`fields`/`order_by`/`group_by`/… anywhere in call_method args) add the DocType of four-element filters to `sc.Doctypes` and their field references to `sc.FilterFields`/`SelectFields`; with any allow/deny_doctypes rule (`hasDoctypeRules`) `checkQueryFields` refuses a non-identifier filter field and a `.` or backtick in fields/order_by, because `link.field`, `child.field` and `` `tabX`.`f` `` join another DocType (v16 query.py ~808-847, v15 db_query). Child-table fields are refused too (no schema to tell them from a Link).
- **MCP confirmation (T1.4c).** `mcpPolicy.confirm` runs after `policy.check` for calls `needsConfirm` marks (delete_doc, bulk_delete, cancel_doc, apply_workflow, share_doc, assign_to, rename_doc with merge; in call_method `destructiveMethods`, `widensAccess` (share.add, set_permission with a true or absent `value`, assign_to.add/add_multiple), `argMethods` by argument value, `mergeMethods` with merge). Values in the question go through `quoted` (strconv.Quote, not Sanitize: escaping keeps the real name visible); call_method shows `keyMethodArgs` first so padding cannot hide them. The audit line's `confirm` says confirmed/unsupported/never. It returns `server.NewInputRequestBuilder(state).Elicit("confirm", …).ToolResult()`; mcp-go bridges that to `elicitation/create` for pre-2026-07-28 clients, so the handler always runs twice (audit `confirm_pending`, then `ok`/`declined`). The state is `exp.nonce.HMAC(site, tool, args)` with a per-process key (`mcpConfirm`); `spend` accepts it once. A retry without a valid state asks again, never proceeds. `canElicit` reads per-request capabilities on modern requests and the session's on legacy ones (which must also implement `SessionWithElicitation`). `confirm: always` without elicitation refuses with `cliEquivalent` (shell-quoted; only the command name if a value has control characters, or a bulk name has a comma or edge spaces). `--confirm` only tightens; `--confirm never` is a usage error. Tests: `mcpTClient` (mcp-go in-process client, `WithProtocolVersion("2025-11-25")` for the legacy bridge).
- **Multi-site MCP (T1.6).** `mcpEnv.sites` holds the served sites (exact config names, default first; one entry, possibly "", for a single-site server). With more than one, `addSiteParam` adds a required `site` (enum) to every tool but the `siteless` ones, `siteFor` refuses a call without one, and each call loads its own site and policy; `registerTools` keeps a tool when any site's policy allows it (`anyAllows`, which allows nothing with no policies). Each site has its own cached client and mutex in `newMCPEnv`. Only the default site signs in at start (others on first call; signing in to all could outlast the detached start's 60 s). `env.site` refuses a Load result whose name differs from the pinned one (Load's case-insensitive fallback would otherwise reach another site). `mcpSites` refuses FFC_API_KEY/SECRET with several sites (`applyEnvOverrides` would put them on every site). The daemon pins the resolved list via `daemonArgs` (`--sites=` per site, CSV-quoted by `csvField`, as for every list flag); `mcp.json` has `sites` and still writes `site` (the default) for older readers. New tools get the `site` argument for free; a tool that works on the server, not a site, goes in `siteless`.
- The stdio server uses `server.NewStdioServer(s).Listen(cmd.Context(), …)`. Do not go back to `ServeStdio` with a context func returning `cmd.Context()`: that dropped the session mcp-go puts in the context (client name, capabilities, elicitation).
- MCP limits: results over 512 KiB are refused with a hint to narrow them (list_docs and run_report rows are cut to fit instead, see T2.7); `run_report` defaults to 500 rows; bulk tools take at most 200 items; `--read-only` registers only read tools (call_method counts as a write).
- The MCP detached-server state file is `~/.config/ffc/mcp.json` (pid, port, site, started_at, log_path, token, instance; 0600, the token is the HTTP bearer secret), guarded by a lock file; the log is `~/.config/ffc/mcp.log`. `ffc mcp stop --force` stops a PID that is alive but not health-confirmed.
- **`desktop/` is a nested Go module** (`github.com/nasroykh/foxmayn_frappe_cli/desktop`). Its path under the ffc module path is what lets it import `internal/` packages; renaming it to an unrelated path breaks that. Wails, Node and CGO must stay in `desktop/go.mod`, never in the root `go.mod` (the CLI release is CGO-free). Root `go test ./...`/`go vet ./...` skip it (desktop.yml runs them); root CI `gofmt -l .` does check its Go files. The root `.gitignore` entry for the `foxmayn_frappe_cli` binary is anchored (`/foxmayn_frappe_cli`) because unanchored it ignored the Wails bindings directory `frontend/bindings/github.com/nasroykh/foxmayn_frappe_cli/`. `ffc update`, the update check and the desktop installer never use GitHub's `releases/latest` (a desktop release may be it): `release.Latest` takes the newest non-draft, non-prerelease release whose tag is `v<digit>…`, so desktop releases need another tag prefix (e.g. `desktop-v0.1.0`). A desktop release must still be published with `make_latest: false` (never GitHub's latest): install.sh (the releases/latest redirect), install.ps1 (the releases/latest API) and every ffc up to v1.11.0 still read releases/latest.
- `mcp_detach_unix.go` / `mcp_detach_windows.go` use build tags. Keep `syscall`/`golang.org/x/sys/windows` fields out of untagged files.

- **Optimistic concurrency (T2.9).** Frappe's `check_if_latest` compares a `modified` sent with a PUT to the stored one and raises `TimestampMismatchError` (417, exit 6); without `modified` there is no check. `edit-doc`, `update-doc --if-unmodified` and MCP `update_doc` `if_unmodified` rely on it; `conflictError` rewords it. `edit-doc` cannot use `callSite` (no spinner while the editor owns the terminal): it uses `newClient` + `CloseQuietly` and `runSpinner` around the reads and the save. Values are diffed against the generated file parsed back (`base`), never against the server JSON, so a round trip is never a change. Only changed fields are sent; a table with any change is sent whole (kept rows as read plus the edits, so no column is lost; new rows without `name`; `idx` from the file order), because a PUT replaces the table. Text fields take the YAML text as written (`0123` stays a string), number fields need a number, a Check takes true/false. Frappe does not refuse a change it will not keep, it drops it: `validate_higher_perm_levels` resets fields at a level the user's roles do not write and v16 `_restore_masked_fields_from_db` restores masked ones (the fake does both, `keepNoWriteAccess`). A fixed table (submitted, not allow-on-submit) refuses added, removed, moved and null rows; a new row equal to a removed row (its `name:` line deleted) is refused, since saving it would replace the row and lose its hidden columns. `update-doc --diff` sends the `modified` it read (unless `--if-unmodified`) and prints the diff only after a successful save. Client: `Download` is `Raw` (streamed, no 128 MiB cap, SitePath/CheckHeaders boundary) plus its own loop of the GET retry policy (`retryableStatus`/`retryableTransport`, http.go; waits from the resty client's retry settings): resty's retries cannot be used with a streamed body (a retried response's body is never closed). One `context.WithTimeout` (the client timeout) bounds every attempt, the waits and the body read, released when the body is closed (`cancelOnClose`); a retry whose wait does not fit in what is left is not made. The body is streamed, not built by resty (which buffers a multipart form twice): `multipartBody` is the form head, an `io.SectionReader` over `FileUpload.File` (or `Content`) and the closing boundary, and resty sees only `http.NoBody`: it reads any other `io.Reader` body whole into memory unless the http.Request has `GetBody` (resty middleware.go getBodyCopy), so the `setStreamedBody` pre-request hook, which runs after resty built the request, puts the stream in place with its exact Content-Length (Go would send it chunked) and no `GetBody`. `ffc upload` (`openUpload`) streams a regular file from disk under the site's limit only; stdin or a pipe is read into memory, capped at the smaller of the site's limit and `maxUploadInMemory` (128 MiB). `AttachFile` needs `Content`.
