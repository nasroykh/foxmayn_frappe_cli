# Customizations and admin views internals

Moved out of the root CLAUDE.md so it loads only when the work touches this area. Notes for contributors and AI agents; the root file keeps the rules that apply everywhere.

- **Customizations (T3.3, `ffc customize pull`/`push`, customize.go and customize_push.go; docs/cli/customize.md).** Facts from the Frappe v16.36.1 source; the planner checked the v15 branch.
  - Names are the same on every site, so documents match across sites by name. Custom Field is `dt-fieldname` (custom_field.py:128-162). Property Setter is `doc_type-(field_name|row_name|main)-property`, and inserting one deletes the existing setter with the same key (property_setter.py:34-43). Workflow, Workflow State, Workflow Action Master and Report are named from a field; the rest keep the name sent (Prompt). naming.py:158 recomputes every non-Prompt name on insert.
  - `is_system_generated`: Customize Form writes 0, while create_custom_field, make_property_setter and the v14 patch write 1. Pull leaves out 1 unless `--include-system` (these are the apps' fields; on acme all 12 Custom Fields and all 181 Property Setters are 1).
  - Standard Report (`is_standard` Yes), Print Format (`standard` Yes) and Notification (`is_standard` 1) are left out: they live in app code and change only in developer mode. Non-standard does not mean user-made: acme's "IRS 1099 Form" and the "Error Log" Notification ship with apps.
  - Workflow, Workflow State, Workflow Action Master and Webhook have no `module` field, and Custom Field and Property Setter's "Module (for export)" is usually empty. So `--module` also selects by the target DocType's module (one DocType list query), as decided.
  - Saving a Server Script checks only the Script Manager role (`only_for`, server_script.py:88). `server_script_enabled` is read only when a script runs (safe_exec.py).
  - A Password field sent empty deletes the stored secret (base_document.py:1361), so a push must never send one. Pull drops Password fields (found in FormMetas, child tables included) and warns when one had a value (Webhook `webhook_secret`).
  - File format: one JSON file per document; sorted keys; no nulls, stamps or `_` keys; LF and a final newline; no HTML escaping. Child rows keep their order and lose their identity.
  - A multi-line top-level string goes to a sidecar file `<base>.<field>.<ext>`, referenced as `{"$file": name}`. Only fields with a `client.ValidIdentifier` name get one. The extension is never `.json` (`webhook_json` is `.jinja`), so sidecars and document files are disjoint.
  - Sidecars that the previous version referenced and this one does not are removed after the writes. The old file may have been edited, so only names matching `isSidecarOf` are removed: `<base>.<identifier>.<known ext>`. Another document's files never match: they end in .json or have one more dotted part.
  - Every file name is checked for case-insensitive clashes before anything is written.
  - Child-row passwords are found through the table field's Options, not the row's `doctype`.
  - Webhook header keys that look like credentials produce a warning (they are Data fields and are written).
  - In module mode the `in` lists go in chunks of 50 (a GET URL). Stale detection also counts files whose target DocType is in the module.
  - `.gitattributes` (`* text eol=lf`) is written when missing, so a Windows checkout keeps sidecars LF.
  - Pull never deletes a JSON file; stale ones in the selection are listed. Names that differ only in case are refused.
  - Push:
    - Every file is read and checked before any request; a bad file is a usage error (exit 2). The file name must be `customFileBase(name).json`, and `$file` must name one of the document's own sidecars. Files and kind folders must be regular files and folders (`readCustomRegular`, Lstat: a link in a cloned repository could point at a secret that push would send), at most 16 MiB. A document whose name differs from `customDerivedName` (Custom Field dt-fieldname, Property Setter doc_type-(field_name|row_name|main)-property, the "field:" autonames) is refused: insert would create it under the derived name, and every later push would try to create it again.
    - Workflow.validate calls set_active (workflow.py:35, 116): saving an active Workflow, on create or update, sets is_active 0 on every other Workflow of the DocType. `workflowDeactivates` lists them in a warning.
    - With --json and no --yes, the plan goes to stderr before the question.
    - Each document is read from the site (404 = create) and normalized like pull. Only the file's keys are compared (`sameCustomValue`: numbers by value; a table is unchanged when every key of every file row matches, so columns a newer Frappe adds do not count) and only changed keys are sent, with the `modified` read (TimestampMismatch is reworded by `conflictError`).
    - A field cleared on the source is missing from the file, so it is not cleared on the target (documented).
    - Keys not in the site's meta (`readCustomMeta`.fields, rows too) are left out with one warning; a top-level one whose value the site already has is silent (legacy columns). Password keys are never sent. Updating a table whose child has Password fields warns: replaced rows lose them. So does replacing rows whose site-only columns have values (`siteOnlyColumns`): they go back to their defaults.
    - Order: `customPushOrder`, then `orderCustomFields` (insert_after within a dt). Writes are sequential (`runBulk`, one worker); failures give exit 8 (`partialError`).
    - Never deletes. With -d, `customExtras` lists the site's documents the folder lacks (selected like pull, default exclusions).
    - Warns when `frappe.core.doctype.server_script.server_script.enabled` answers false (null: no Server Script permission, no warning), and when a Webhook is created with `enable_security`.
  - Fake: the kinds are registered with AddDocType, plus `DocField("Webhook", "webhook_secret", "Password")`; push tests declare the meta with `customTMeta`. Contract: `contractCustomizePull` and `contractCustomizePush` (round trip, edit, table replacement, recreate; contract_customize_test.go).

- **Admin views (T3.8, `ffc health`/`jobs`/`errors`/`scheduler`, admin.go; docs/cli/admin.md).** Facts from the Frappe v16.36.1 source; the v15 branch has the same files. All need System Manager (403 = exit 5).
  - System Health Report is a virtual Single: `GetDoc("System Health Report", "System Health Report")` runs load_from_db, which calls `only_for("System Manager")` and enqueues a `frappe.ping` job (at_front) to test the queue. So `health` writes one job; never run it on a site that must stay untouched. Each check is wrapped in `health_check`: a failure msgprints and leaves its fields unset. `healthAttention` derives the attention list (test job not queued, no workers, scheduler not Active, oldest_unscheduled_job, failing scheduled jobs, workers with failed jobs, failed emails, errors in 24 h).
  - RQ Job is a virtual DocType. Its get_list ignores `fields`, needs `order_by` (None is a TypeError) and slices with an unconverted page_length, so a GET list (string params) is a TypeError. `fetchJobs` POSTs `frappe.client.get_list` with a JSON int `limit_page_length` and `order_by: "creation desc"`. v15 differs (rq_job.py on version-15, db_query.py:404-420): get_list gets DatabaseQuery's `__dict__`, reads `page_length`/`start`, which are never in it, so it returns the first 20 matching job ids in queue and registry order, sorted by modified afterwards; `make_filter_dict` reads four-element filters only (three elements are an IndexError), so ffc sends `["RQ Job", field, op, value]`. On a full v15 page `fetchJobs` warns (`v15JobPage`, version from `serverInfo`). `cleanJob` drops `_` keys and doc stamps. GetDoc on a job id works (`jobs -n`). Statuses: queued, started, failed, finished, deferred, scheduled, canceled. Redis keeps finished and failed jobs only for a while.
  - Frappe stores times naive in the System Settings `time_zone` (get_system_timezone). `frappe.client.get_time_zone` answers the defaults' zone, which can differ (acme: Asia/Kolkata vs Africa/Algiers), so `siteTimeAgo` reads System Settings and formats `adminNow() - d` in that zone (`time/tzdata` embedded for Windows).
  - Error Log: a REST GET does not mark it seen (only getdoc's onload does). v16 adds `metadata` and `fingerprint`.
  - `frappe.utils.scheduler.get_scheduler_status` is whitelisted without a permission check and answers `{"status": "active"|"inactive"}`; inactive with maintenance_mode, pause_scheduler, or the scheduler disabled. Scheduled Job Type names are hashes on v16: show `method`.
  - Scheduled Job Log exists only for job types with `create_log`: validate forces it for every frequency except All and Cron, and update_scheduler_log returns without a log when it is 0, failures included. `scheduler` counts failed logs (newest `schedulerFailureCap` = 1000, warns at the cap); failures of All/Cron jobs without create_log show only in `jobs --status failed`.
  - MCP (admin tool set, all actRead): `site_health`, `list_jobs`, `list_errors`, `scheduler_status` share fetchHealth/fetchJobs/fetchErrors/fetchScheduler. `adminDoctypes` adds the DocTypes each reads to the scope (System Settings for the time zone; site_health also Error Log, RQ Job, Email Queue and User, whose data the report aggregates). list_errors applies the DocType rules to each entry's `reference_doctype` (`{errors, hidden_by_policy}`; `name` of a hidden one is refused). Lists cap at `mcpAdminLimit` (100) and carry only the traceback's last line (`error`, scheduler_status too); `name` returns the whole record. A job's arguments can hold any DocType's data; only RQ Job is checked (documented). String arguments go through `stringArg`. site_health stays a read although it queues frappe.ping (as the desk page does; documented).
  - Fake: `adminTReport`/`adminTJobs` and `HandleMethod` for get_list (a GET or a missing order_by is the TypeError); `adminNow` is the clock seam. Contract: `contractAdmin` (contract_admin_test.go).
