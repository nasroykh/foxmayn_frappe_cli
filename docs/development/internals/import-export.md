# Export and import internals

Moved out of the root CLAUDE.md so it loads only when the work touches this area. Notes for contributors and AI agents; the root file keeps the rules that apply everywhere.

- **Export (T3.1, `ffc export`/`import-template`, export.go and import_template.go; docs/cli/export.md).** Facts from the Frappe v16.51.0 source (local bench); the v15 branch checked on GitHub where noted.
  - Data Import file layout (importer.py `parse_next_row_for_import`): the first row is the header; a document is its first row plus the following rows whose parent columns are all blank (more child rows); a row with any parent value starts the next document. Headers match by fieldname (`build_fields_dict_for_column_matching`): parent `fieldname`/`name`, child `table.fieldname`/`table.name`. ffc writes `name`, the parent fields, then per table `table.name`, `table.<field>`.
  - Cells mirror exporter.py `add_data_row` and csvutils.py: Duration through `format_duration(flt(v), hide_days)` (utils/data.py: cint truncation, zero parts dropped, "" for 0, "-" prefix) and then every string through `escape_formula_injection` (leading `'` before `= + - @ 	 `; numbers are not strings, so not escaped; a negative Duration is). `read_csv_content` undoes it with `unescape_formula_injection`; both exist on the v15 branch. Every row has every column; null is empty. v16 also html2texts Text Editor (v15 does not); ffc's CSV keeps the HTML. JSON/NDJSON are raw values, rows nested without parent/parentfield/idx.
  - Columns: like the desk picker (data_exporter.js `get_columns_for_picker`: no_value types, `lft`/`rgt`, `is_virtual` out; read-only and hidden stay) plus readability (`FieldAccess`, level 0 when roles are unknown) and no Password. Meta from `FormMetas` (getdoctype: custom fields and property setters applied, child metas included, any user with read), not fetchSchema (needs DocType read). `FormField.HideDays` for Duration. Unknown field/table = usage error; unreadable = 403 PermissionError APIError (exit 5), like aggregate.
  - Children: per page of parents and per table, `ChildRows` POSTs `frappe.client.get_list` (client.py:27; `parent` → `parent_doctype`, so the parent's read permission applies) with filters parent in names (chunks of 500), parentfield, parenttype, `order_by: idx asc`, `limit_page_length: 0`; grouped by parent in parent order. Parents page with GetList, default order `creation asc, name asc` (Frappe's exporter uses creation DESC or the user's list settings).
  - `download_template(doctype, export_fields, export_records, export_filters, file_type)` (data_import.py:336, whitelisted, any method; same on v15): `export_fields` is required in practice (None crashes), a dict `{DocType: [...], tablefield: [...]}` where "name" must be listed to get the ID column; `export_records` "blank_template" (header only), "5_records", anything else = all matching; needs read, and with data `can_export` (System Manager always). Excel answers binary; ffc POSTs a JSON body through `Raw`, checks "PK" (`checkXLSX`), refuses a terminal before sending (`exportTarget`), and `--xlsx` refuses --output/--json/--jq (`refuseFormat`, FFC_OUTPUT ignored), --limit/--order-by/--page-size. Do not use `frappe.desk.reportview.export_query` (report shape, not importable).
  - Output: `writeAtomic` (files.go, shared with saveAtomic) for `-o` (0600; refused before any request without --force); stdout cells sanitized only on a terminal, like ListStream. `output.ListStream.Record` writes a raw CSV/TSV record. Fake: `childList` (frappetest/export.go) answers get_list with `parent`; tests answer download_template with `Handle`. Contract: `contractExport` (contract_export_test.go).
  - Review notes: the fake's childList checks neither the parent's read permission nor permlevels (real Frappe only, contract). A user `--order-by` gets `, name asc` unless it already sorts by name (`sortsByName`). FFC_OUTPUT is ignored (only an explicit `--output`/`--json`). TSV is not importable (Frappe reads CSV and Excel) and escapes backslash, tab and newline.

- **Import (T3.1, `ffc import -d DT FILE|- --mode insert|update`, import.go and import_parse.go; docs/cli/import.md).** Client-side, mirroring Frappe v16.51.0 `importer.py` (local bench). Facts and decisions:
  - Layout as export (parse_data_from_template :823, parse_next_row_for_import :971): blank rows skipped, first non-blank row is the header, a row with any non-ignored document value, or an owner/docstatus value (Frappe's get_column_indexes :1817 counts them; ffc still ignores the value), starts a document. A row whose values are all in ignored or untitled columns is a problem, never dropped. Cells `strip()`ed and `unescape_formula_injection`ed (csvutils.py:27, :124), "" = not set. Go csv with LazyQuotes and FieldsPerRecord -1; rows are file lines (`FieldPos`), JSON items, NDJSON lines.
  - Headers (`headerMap`, build_fields_dict_for_column_matching :2106, same insertion order so the same header wins): name/ID, label (first field wins), fieldname, "Label (fieldname)", table.field, "Label (Table label or fieldname)", table.name, "ID (Table)", "ID (autoname field label)". Untranslated only. Decision: "name"/"ID" always mean the document name (Frappe maps them to a `field:x` autoname field, :2240). owner/docstatus (Frappe matches them) and creation/modified/modified_by/idx, child parent/parenttype/parentfield/idx are ignored with a warning. Unknown, duplicate (two columns → one field) and table-only headers are one usage error (exit 2); Frappe would skip them with an info warning. Password fields (`importMeta.passwords`, parent and child; every header form and JSON key) are the same usage error: the site answers them masked, so update would resend them every time and the plaintext would show in notKept and dry-run plans. Their values are never printed.
  - Values (`convertImportValue`, parse_value :1693, validate_value :1614): Check words, else 0 or 1 only; Int/Long Int whole numbers only (Frappe's cint truncates, ffc refuses); Float/Currency/Percent plain numbers only (v16 `_parse_number` also takes the system number format's grouping, ffc does not); Date/Datetime one format per column (guess_date_format_for_column :1927, utils/data.py:2652 guess_date_format; ties → first seen, Frappe's set order is arbitrary; nothing guessed → %Y-%m-%d, :1993), parsed by a strptime port (Python's directive regexes, `\s+` for a space), seconds with and without a fraction are one format (the site sends a fraction only when non-zero, so exports mix them; Frappe would refuse the minority), sent as YYYY-MM-DD / YYYY-MM-DD HH:MM:SS[.ffffff] (`parseDate`); `convert` warns about a column whose every value also reads with %d/%m swapped and some value then differs (`ambiguousDates`); Time `normalTime` H:MM, HH:MM, HH:MM:SS[.f{1,6}] → HH:MM:SS[.ffffff] (zero fraction dropped), and `sameImportValue` normalises the site's "9:05:00" too; Duration DURATION_PATTERN (:32) plus a leading "-" (export writes one), duration_to_seconds; Select in options (stripped, value_mapping.py:111); Link checked; Dynamic Link not (Frappe neither).
  - Link checks (`importJob.checkLinks`, value_mapping.py get_invalid_link_select_items): GET list per target, `name in` lists split by escaped length (`linkChunks`, `linkURLBudget` 3500 bytes of filters), compared lower-case (MariaDB); 403 on the target → warning, the site checks on save. Uses GET so `--dry-run` (writes scope) still runs it; ChildRows' POST get_list would be held back. GET list applies User Permissions where Frappe's check (get_all) does not, so the problem says "(or your User Permissions hide it from you)" (decision: no flag). A Link to the imported DocType may name a document of the file only on insert when its name is kept (`fileNames`: sendName, nameField, or the `field:x` column's value) and it comes earlier; a later or the same document is a problem. Such links (`sameFile`) force one worker, so the writes keep file order (warning when --concurrency > 1).
  - Everything is read and checked before any write; problems (row, column, value, reason) → stderr lines or `{"problems":[...]}` on stdout, then `client.StateError` (exit 6), nothing written.
  - Insert: REST `set_new_name` (model/naming.py:158) drops a name unless autoname is prompt/UUID (Data Import keeps it only via `frappe.flags.in_import`, importer.py:122), so ffc sends the name only then, puts it in the `field:x` field when the file has no x column, else ignores it with a warning. Child row names never sent; a child row with only a name is left out (`sentRows`).
  - Update (update_record :597): GetDoc, changed fields only (`sameImportValue`: sameValue, Link EqualFold), a table with rows in the file is sent whole when anything differs (kept rows = site row + file values with name, new rows without, idx = file order, left-out rows removed; a table with no rows in the file is untouched, so import cannot empty a table); `modified` sent → TimestampMismatch → `conflictError`. Nothing changed → "unchanged", no PUT (Frappe throws "No changes to update"). `notKept` warns per field and per table cell (saved rows vs sent rows by position, file columns only, also on insert; a row count difference is one warning). A table whose file rows carry no row names, for a document with rows in it on the site, is a problem found before any write (`checkUnnamedRows`: GetDoc per such document, 404 left to the write): it would replace the rows and reset every column the file lacks; the reason points to `ffc export` (writes table.name). A row name twice in a doc, a doc name twice (lower-case) or a missing name are problems.
  - Writes: `runBulk` (bulkFlags: --concurrency default 1, --fail-fast), per-doc `importResult` {row,name,status created|updated|unchanged|failed|interrupted|skipped,submitted,warning,error}; any failed/skipped → partialError (8). No confirmation (like bulk-create/update --data), no `--yes`. --submit: meta `is_submittable` (FormMeta.IsSubmittable, new) else usage; active Workflow → StateError before writes; drafts only, unchanged drafts too; submit failure after a write = failed with "created as X, but the submit failed".
  - --dry-run: own loop (`importJob.dryRun`), not planAll (an unchanged doc returns nil, which planAll treats as an error): each doc stops at its first write; results + `printPlan` (update requests carry Changes), `{"dry_run":true,"requests",...}` in JSON; a doc that would fail → exit 8.
  - FormMeta gained Autoname, IsSubmittable and FormField.Label (getdoctype). Fake: no change needed (DocTypeFlags for autoname/is_submittable, FieldProp label/options, list `in`); the fake's `in` is case-sensitive, so the case-insensitive Link match is real-MariaDB only. Contract: `contractImport` (contract_import_test.go, after export, before workflow), cleanup by ref_no marker.
  - **`--server` (PR3, import_server.go, client/dataimport.go).** Frappe's Data Import does the parsing and writing. Source checked: v16.51.0 (local bench), v16.36.1 and version-15 (GitHub). Facts: Data Import is System Manager only; `validate_doctype` (v16.51 data_import.py:152, v15 :60) refuses BLOCKED_DOCTYPES (CORE_DOCTYPES minus User/Role/Print Format), DocTypes without allow_import (417) and users without import permission (403). Saving `import_file` parses the file in validate (v15/v16.36 `validate_import_file`, v16.51 `get_importer`), sets payload_count (documents); only csv/xlsx/xls are read (importer.py read_content). `get_preview_from_template(data_import, import_file=None, google_sheets_url=None)` (v16.51 :235) answers `{data (≤10 rows), columns, warnings, total_number_of_rows}` (total only when cut before v16.51); warnings are `{row|rows, col, field, message (HTML), type}` and import_data blocks on every type but "info" (a missing type blocks). `form_start_import` (:244, write perm) → `start_import` (:196): `frappe.throw` "Scheduler is inactive" unless developer_mode/in_test (then it runs in the request, now=True); enqueues on the **default** queue (not long; all three versions), job id `data_import||<name>` (v15 `::`), not re-enqueued while queued/started (`is_job_enqueued`), returns true/false. `get_import_status(data_import_name)` (v16.51 :402, v16.36 :278, v15 :227) → `{status, total_records = payload_count, success?, failed?}`; v16.51 adds processed_records/inserted/updated. `get_import_logs(data_import)` (v16.51 :457, limit 1000, optional status; v15/v16.36 limit_page_length 5000) rows `{success, docname, messages, exception, row_indexes}` with `messages = json.dumps(message_log)` (msgprint dicts; a success stores `json.dumps("[]")`, a JSON string) and `row_indexes` a JSON list (create_import_log, v16.36 importer.py:1335). Status flow v15/v16.36 (importer.py import_data): blocking warnings → `template_warnings` set, status untouched (Pending), return; first success sets "Partial Success" mid-run; the end sets Error/Partial Success/Success/Pending from the logs; the job wrapper sets Error (log_error "Data import failed") or Timed Out. v16.51: "In Progress" at the start, blocked → status Pending explicitly, final "Partial Success" is final even with fewer logs than total (skipped rows). New sites have the scheduler disabled (installer.py `_new_site`: toggle_scheduler(False); the setup wizard enables it), so contract.yml runs `bench --site frontend enable-scheduler`. Deleting a Data Import deletes its logs (on_trash) and attached Files (delete_doc remove_all).
  - Decisions: input CSV and .xlsx only (JSON/NDJSON/TSV/xls are usage errors naming the client engine or the fix); no client-side header check (Frappe's preview reports it). Steps: MaxFileSize + openUpload (size checked before anything is created) → NewDataImport → UploadFile (private, field import_file) → PUT import_file → preview; a failure in these steps or blocking warnings deletes the Data Import (`discardDataImport`; not with --preview, which keeps it and prints `ffc import --server --resume NAME`). `--dry-run` refused (creating the Data Import is a write), `--concurrency`/`--fail-fast` refused, `--preview/--wait/--mute-emails` need --server, `-d`/`--mode` are checked in RunE (MarkFlagRequired removed: --resume needs neither; messages kept as cobra's). `--resume NAME` implies --server, takes no FILE nor --mode/--submit/--mute-emails/--preview/--format; Pending + template_warnings → print them, exit 6; Pending → start (a no-op when queued/running) then wait; otherwise wait (returns at once when finished: report only, never a retry). StartDataImport on a 417 asks get_scheduler_status (translation-proof) → StateError (exit 6) with the enable + resume hint; the Data Import is kept. Wait: DataImportPollStart 1 s doubling to 5 s, bounded by --wait (default 10m, ≥1s); done when Success/Error/Timed Out, Partial Success with processed_records (v16.51), or success+failed ≥ total (not while Pending/In Progress); Pending with no logs → GetDoc for template_warnings (blocked). `Final()` derives the status from complete counts (v15 may still read Partial Success). Timeout → codeError exit 7 with `resumeHint`. Report: rows `{rows, name, status created|updated|imported|failed, message (messages joined, else the traceback's last line)}`; failed > 0 → partialError 8 (all failed too); Error/Timed Out with fewer logs than total → StateError 6; blocked → 6 with `{status: Blocked, warnings}` on stdout under --json. 403 hint names System Manager (`dataImportHints`). Progress: static spinner title; without a spinner (not a TTY) a stderr line per status change unless --quiet. No MCP tool. Fake: `Site.DataImports(DataImportRun{Rows, Payloads, Warnings, RunWarnings, TemplateError, SchedulerInactive, Polls, Logs, Status, InProgress})` (frappetest/dataimport.go; saveHooks on create/update of Data Import; calling it again revives jobs waiting with Polls < 0), `DataImportJob(name)`. Contract: `contractImportServer` (after import; skips when the scheduler is inactive; fixture DocType now allow_import with import permission; teardownContract deletes the fixture's Data Imports, which link the DocType).
