# Data command internals

Moved out of the root CLAUDE.md so it loads only when the work touches this area. Notes for contributors and AI agents; the root file keeps the rules that apply everywhere.

- **Identity and permissions (T2.4).** Frappe signatures (v16.36.1 source): `frappe.utils.change_log.get_versions()` (change_log.py:105, any logged-in user; `{app: {title, description, branch, color, logo, version}}`), `frappe.auth.get_logged_user()` (auth.py:451), `frappe.client.has_permission(doctype, docname, perm_type="read")` (client.py:325, returns `{"has_permission": bool}`; **docname is required**, omitting it is a 500 TypeError, so a DocType-level question cannot be asked: `DocTypePermission` applies the getdoctype `permissions` rows (permlevel 0) to the user's roles instead, `basis: "doctype"`), `frappe.client.get_doc_permissions(doctype, docname)` (client.py:336, `{"permissions": {...}}`; a document the controller refuses comes back as `{"null": 0}`, which `DocPermissions` turns into an empty set). `has_permission` is true for Administrator before the DocType or document is looked up; for others a missing document is 404 and an unknown DocType 403. `has_permission` and `get_doc_permissions` can disagree (a User may edit their own User document: true vs write 0): `has_permission` is the authoritative one. All of these are GETs, so a dry run does not hold them back. `EvalDocTypePermission` mirrors `get_role_permissions` (permissions.py:318-345): an `if_owner` row narrows a right only when no non-`if_owner` applicable row grants it and never `create` (select/read stay allowed with `owner_only`, other rights are denied with `owner_only`); `select` is implied by `read` (213); `submit`/`cancel`/`amend` need `is_submittable` and `import` `allow_import` (Frappe itself checks only submit and import; ffc also zeroes cancel/amend); a child table (`istable`) is a `client.ChildTableError` (exit 2: `has_permission` delegates to the parent, `has_child_permission`). Desk User is added only when the User doc's `user_type` is readable and is System User (it is permission level 1); otherwise `DocTypePermission.Note` says what it left out. On the `-n` path `parsePerm` accepts any lower-case identifier (custom v16 permission types); at DocType level only `client.PermTypes`. `ffc can` and `check_permission` share `checkPermission`; the MCP tool uses the argument names `doctype`/`name`, so `scopeOf` and the DocType policy apply unchanged. MCP `whoami` reads the User DocType, so `scopeOf` adds `User` to its scope (deny_doctypes/allow_doctypes for User apply); it gets its site from `siteFrom(ctx)` (`withSite`, set next to `withPolicy` in `env.run`) so it works per site with several sites. whoami and every URL printed use `redactedURL`.

- **Server version cache.** `serverInfo` caches get_versions per site for 24 h (`serverCacheTTL`) in `os.UserCacheDir()/ffc/<sanitized name>-<hash of the exact name>/<credentialID>/server.json` (dir 0700, file 0600, atomic write; a nameless env-only site is keyed by its URL). An entry is ignored when damaged, expired, dated in the future, or read from another URL; `--refresh` (whoami, doctor) skips it; a 404, 5xx or transport error from the versions call drops it (`serverChanged`). The directory comes from the package var `sitecache.UserCacheDir` (default `os.UserCacheDir`); TestMain and `cacheTEnv` (cmd) and the desktop services TestMain point it at a temp dir, so no test touches the real cache on any OS. Version-dependent behaviour calls `serverInfo(...).FrappeMajor()`; never build a cache path from a raw site name (`sitecache.DirName`). doctor does not use the cache.

- **doctor.** Check ids (`config.file`, `config.dir`, `config.parse`, `config.lock`, `net.tls`, `net.reachable`, `net.clock`, `auth.valid`, `auth.oauth_token`, `server.versions`, `server.api_v2`, `mcp.daemon`, `mcp.state_file`, `update.check`) are a JSON contract: never rename. fail makes exit 1, warn does not. It changes nothing: no lock removal, no stale MCP state cleanup (`mcpDaemonStatus` is shared with `ffc mcp status`, which does clean up), no OAuth refresh (it builds its client with `client.New` from the stored config on purpose, reports an expired token as a warning, and skips `auth.valid` then), no version cache read or write (always live; no `--refresh`), and a password site's login is closed with `CloseQuietly`. `net.reachable` and `net.tls` come from one GET of `frappe.ping` through the normal transport (proxy honoured); `resp.RawResponse.TLS` gives the certificate and a changed final URL is a failure with the final site URL as the hint. The MCP state file mode is checked whenever the file exists. Probes that need the site are skipped when `net.reachable` fails. Never print a secret: parse errors have their backtick-quoted values stripped, URLs go through `redactedURL`, the MCP token and OAuth token are never included. `ping` now also calls `get_logged_user` and exits 3 on rejected credentials or Guest, because `frappe.ping` works without login (documented behaviour change in docs/cli/sites-and-settings.md); `ffc whoami` as Guest prints its result, then exits 3 too.

- **Lifecycle:** every state change goes through Frappe's whitelisted methods (`frappe.client.submit` with the document as read, so the timestamp check applies; `frappe.client.cancel`, `rename_doc`, `frappe.model.workflow.*`, the Deleted Document `restore`). amend-doc and copy-doc build the copy client-side from GetDoc (`clean`): the v2 `/copy` route ignores its `ignore_no_copy` query parameter, so both read the meta from `frappe.desk.form.load.getdoctype` (whose data is in `docs`, not `message`; the fake returns it with `frappetest.Response`). Like the desk, a copy never carries Password fields (masked) or `lft`/`rgt` (a tree node keeping them corrupts the nested set); copy-doc also drops "no copy" fields, amend-doc keeps them and sets `amendment_date` when the DocType has it. Fake meta: `DocField`, `NoCopy`, `ChildTable` (also stamps row identity), `AllowOnSubmit`. An amendment is `<name>-1`, an amendment of `<x>-<n>` is `<x>-<n+1>`; a second amendment of the same document is a duplicate. `restore` may give a hash- or series-named document a new name (`Deleted Document.new_name`). submit-doc/cancel-doc refuse a DocType with an active Workflow (StateError); a 403 reading Workflow skips the check. `discard` exists only in v16: the missing-method error is translated, so it is detected by the method name in a 417 and wrapped with ErrNeedsV16 (exit stays 6). Workflow bulk is client-side (`bulk_workflow_approval` reports per-document failures only as msgprint), and so are `bulk-submit`/`bulk-cancel` (`submit_cancel_or_update_docs` has the same flaw): `refuseWorkflow` runs once with an empty name, each document is read first (`blocked` by docstatus gives a StateError result instead of the server's DocstatusTransitionError, and keeps a dry run to documents it would change), `--filters` gets `docstatus` 0 (submit) or 1 (cancel) added by `withDocstatus`, and statuses are `submitted`/`cancelled`/`error`/`skipped`/`interrupted`.

- **`bulk-create --atomic` (insert_many).** Frappe v16.36.1, same on version-15: `frappe.client.insert_many(docs)` (client.py:231-242; a JSON string or a list) refuses more than 200 (`frappe.throw` "Only 200 inserts allowed in one request", 417) and returns the names in order; each item goes through `insert_doc` (client.py:528-544) as its own `doctype`, and an item with `parent` and `parenttype` is appended to that existing parent, which is saved. The request is one transaction: rolled back on an exception, committed on success (app.py:181-184, 458-466). It does not hold when a controller hook calls `frappe.db.commit()` or when DDL runs (inserting a Custom Field or DocType: MariaDB commits implicitly); docs/cli/bulk.md says so. `client.InsertManyDocs` forces `doctype` to the -d DocType on copies, and refuses another `doctype`, a parent row and more than `MaxInsertMany` (usage errors in the CLI, before any request); no meta is read, so a child-table DocType is not refused beyond that. A failure is one error with no report: `atomicError` says "nothing was created" for a 4xx refusal or a 500/501 with Frappe's exc_type (rolled back; exit by class), "probably created" for a success answer ffc cannot read (`client.ErrUnusableReply`), and "may or may not have been created" otherwise (transport error, 408, 499, any 502 and above including CDN 520-524, a 5xx without exc_type; exit 7, suggests `--timeout`). `--concurrency`/`--fail-fast` are usage errors with it. A dry run plans the one POST. Fake: all-or-nothing by removing what the batch inserted and restoring the name counter and clock. Contract: `contractBulkCreateAtomic` (no Link field on the fixture, so the invalid item is a Select value outside its options).

- **Local cache and completion (T2.8).** Shell completion (`completion.go`, cobra `__complete`) and MCP `completion/complete` (`mcp_completion.go`) read only the config file and the cache: never a request, never a login (a password site would log in on every Tab), never a cache write; a missing or expired entry completes nothing (`ShellCompDirectiveNoFileComp`). Use `loadSiteConfig`, never `loadSite`/`newClient`, there. Flags are matched by name in `registerCompletions` (any command's `doctype`, and `fields` next to it), so a new command gets completion free; it runs in `execute` under `completionOnce` because every init must have run. The cache (`meta_cache.go`) shares server.json's dir and rules (`sitecache.Dir` = `sitecache.Root`/`sitecache.CredentialID`: per site and per login, never a secret in the path, so one login never reads another's lists or schemas; `sitecache.Drop` on site remove/rename/edit and site add/init, called by `sitesetup.Store` through `DropCache` (`siteStore`); `sitecache.DirName` for the DocType file name, URL binding, damaged/expired/future-dated/oversized ignored, 0700/0600, atomic) and decodes with UseNumber. Writers: `list-doctypes`/`list-reports` via `listDocsTo` + `listCacher` only for a complete unfiltered list (no `--module`; `--all`, `--limit 0`, or fewer rows than the limit); `get-schema` (`loadSchema`) and `cache warm`. get-schema serves a hit with no client at all (so no credential or DocType-exists check: documented, `--refresh` checks) and the same stdout/stderr; a hit touches the file (`touchSchemaCache`) so eviction is least recently used (it caches the compact view, the table rows and the warnings; `--full` always fetches, `--refresh` skips the read; `client.DebugNote` says "from the local cache" under `--debug`). MCP `get_schema` neither reads nor writes the cache (a long-lived server must not give a model an hour-old schema to write with). MCP completion offers only what the call would be allowed: a site whose policy allows the template's/prompt's tools, DocTypes `doctypeAllowed` (write for prompts that need a write tool), reports with a known, allowed `ref_doctype` when DocType rules exist (as `checkReport`); at most 100 values. Documents and `-n/--name` are never cached or completed. Values from the site with control/invisible characters are never offered (`matching`).

- **get-doc --fields / MCP get_doc fields (T3.6)** go through `fetchDocFields` (get_doc.go): `client.GetValue` (GET `frappe.client.get_value`, `fieldname` JSON list, `filters` `{"name": n}`; client.py:121, v16.36.1) when every field is a `client.ValidIdentifier`, the DocType is not a Single (`name == doctype`) and not in `hookedDoctypes` (frappe/hooks.py `has_permission`: get_value checks DocType-level `has_permission` and runs a list query, so per-document hooks never run), and `--keys` is within `--fields`. `name` is always asked for, and any `*APIError`, an empty answer, a missing key or an answer whose `name` is not the requested one falls back to GetDoc + `filterKeys`, so output and exit codes match the old path (a virtual DocType's controller may ignore the filters: RQ Worker answers its first worker for any name, seen on acme). Null values are dropped (GetDoc's answer omits them; the contract test caught it). `_`-prefixed fields (`_seen`, ...) never go to get_value: a table may lack them (500 Unknown column). Seen on v16 (acme, 2026-10-07): a child-only field is a 417 DataError, a Table field is dropped (only `name` comes back for `["items"]`), plain fields are byte-identical to GetDoc. v15 drops a field above the user's permlevel (missing key), v16 raises PermissionError. Remaining gap, documented: an app's own `has_permission` hook (the same gap as list-docs). Fake: `getValue`; contract: `contractGetValue`.

- **Optimistic concurrency (T2.9).** Frappe's `check_if_latest` compares a `modified` sent with a PUT to the stored one and raises `TimestampMismatchError` (417, exit 6); without `modified` there is no check. `edit-doc`, `update-doc --if-unmodified`, MCP `update_doc` `if_unmodified` and a `modified` key in a `bulk_update` item rely on it; `conflictError` rewords it (per item for `bulk_update`). A copy saves a new document, so Frappe checks nothing: MCP `copy_doc`/`amend_doc` `if_unmodified` is checked by ffc (`client.checkUnmodified`, a `StateError` with the same "was changed on the server since" wording, nothing created). `edit-doc` cannot use `callSite` (no spinner while the editor owns the terminal): it uses `newClient` + `CloseQuietly` and `runSpinner` around the reads and the save. It refuses without a terminal (`editInputDisabled` = `inputDisabled`), writes the YAML to a 0600 file in an `os.MkdirTemp` dir removed on every return (SIGINT cancels the context, so defers run), and reopens a file that does not parse with `# ERROR:` lines on top (always 2, so the reported line numbers match); an unchanged file after an error gives up (exit 2). Values are diffed against the generated file parsed back (`base`), never against the server JSON, so a round trip is never a change. Only changed fields are sent; a table with any change is sent whole (kept rows as read plus the edits, so no column is lost; new rows without `name`; `idx` from the file order), because a PUT replaces the table. Text fields take the YAML text as written (`0123` stays a string), number fields need a number, a Check takes true/false. Frappe does not refuse a change it will not keep, it drops it: `validate_higher_perm_levels` resets fields at a level the user's roles do not write and v16 `_restore_masked_fields_from_db` restores masked ones (the fake does both, `keepNoWriteAccess`). So edit-doc offers only `FieldAccess.Writable` fields (level-0 unmasked ones when the roles cannot be read) and `notKept` compares the saved document with what was sent and warns instead of printing success. A fixed table (submitted, not allow-on-submit) refuses added, removed, moved and null rows; a new row equal to a removed row (its `name:` line deleted) is refused, since saving it would replace the row and lose its hidden columns. `update-doc --diff` sends the `modified` it read (unless `--if-unmodified`) and prints the diff only after a successful save. A cancelled edit prints `{"cancelled":true,"reason":…}` in machine output. `$VISUAL`/`$EDITOR` go through `splitCommand` (quotes, backslash outside Windows, no shell).

- **Search (T2.2).** `ffc search TEXT... [-d DT] [-l N]` and the MCP `search` tool share `runSearch`/`validateSearch` (search.go). With a DocType it is `frappe.desk.search.search_link` (GET; `doctype`, `txt`, `page_length`; answers `[{value, description, label?}]`: honours search_fields, title, link queries and user permissions), without one `frappe.utils.global_search.search` (GET; `text`, `limit`; answers `[{doctype, name, content, rank, title?, image?}]`, `content` is `Label : value ||| ...`, `rank` a `json.Number`; the text is split on `&` into separate phrases, each returning up to `limit` hits: `runSearch` cuts the combined list to the limit and `validateSearch` allows at most `maxSearchPhrases` (5) phrases). Caveats, documented in docs/cli/search-and-aggregate.md and skills/ffc-reports-api: search_link is `@http_cache(max_age=60)` (`Cache-Control: private,max-age=60,stale-while-revalidate=300`; a dev server overrides it with no-store). ffc keeps no HTTP cache, so only a caching proxy or CDN in front of the site makes a result up to a minute old; global search covers only DocTypes in Global Search Settings and fields flagged `in_global_search`, so an empty answer proves nothing. search_link treats `page_length <= 0` as 25000, so ffc requires `--limit >= 1` (the MCP tool also caps it at 100: global search loads every hit's document). An unknown DocType is a real 404 DoesNotExistError (exit 4). The tool is `actRead`; `scopeOf` records `doctype` when given, so policy.check applies. A global search names no DocType, so `env.run` stores the policy in the call's context (`withPolicy`) and the tool filters hits with `mcpPolicy.filterDoctypeRows` (allow/deny lists from config and flags; a hit without a DocType is dropped) and answers `{results, hidden_by_policy}`. `policyFrom` returns `(policy, ok)`: a tool must fail without one, never fall back to the zero policy (it allows everything). Fake: `Site.SearchFields`, `Site.GlobalSearch` (substring match standing in for MySQL full-text); `HandleMethod` overrides both.

- **Aggregates (T2.3).** Frappe v16 refuses an SQL function written as a string in list `fields` (417 ValidationError "SQL functions are not allowed as strings in SELECT", `_validate_select_field`, frappe/database/query.py ~2156) and takes `{"SUM": "f", "as": "a"}` (upper-case key from `FUNCTION_MAPPING`, query.py ~179; a lower-case key is read as a child-table query; `"*"` only for COUNT; the argument must be a plain fieldname, `SIMPLE_FIELD_PATTERN`). v15 runs fields as SQL text and a dict dies in `reportview.validate_fields` (lru_cache: 500 TypeError "unhashable type: 'dict'"); its `count(*)` fails there too ("*" is no field), so the string form counts `name`. It leaves every name bare unless `filtersJoin` says a filter can join (dotted or backticked field, four-element filter on another DocType, unreadable filters; a bare `name` would then be ambiguous), and then qualifies fields, group_by and order_by as `` `tabX`.`f` `` except inside `min(`/`max(`: v15's `extract_tables` (db_query.py:768) takes the text before the first `.` of a field holding `tab` and `.` as a table unless it contains `count(`/`sum(`/`avg(`/…, so ``min(`tabX`.`f`)`` is the table "(`tabX`" and a 404 "DocType (`tabX` not found" (the fake mirrors it, `v15ExtractTables`). For group_by/order_by: v15's `ORDER_GROUP_PATTERN` (db_query.py:71, checked at 1542) refuses any character outside `[a-z0-9-_ ,`'".()]`, so a qualified non-ASCII DocType name is "Illegal SQL Query" (only legacy DocTypes: new names are ASCII letters, digits, space, `_`, `-` since v15, START_WITH_LETTERS_PATTERN; with a join and such a name v15 cannot group at all). v15 also refuses `if`/`like`/`regexp`/`rlike` as words there (1559), so the string syntax refuses a group field of that name client-side. v15's `reportview.validate_fields` (reportview.py:131-133) silently removes a field above the user's permlevel from `fields` (an aggregate disappears; grouping by one is a PermissionError since `validate_fieldlevel_permissions_for_sort`, db_query.py:1578), while v16 raises PermissionError; on v15 the dropped aggregate is then missing from the rows, or MariaDB fails with 500 OperationalError 1054 "Unknown column '<alias>' in 'ORDER BY'". `runAggregate` therefore reads `client.ReadableFields` first and `AggregateQuery.CheckReadable` refuses a group/aggregate field that is a DocField the user may not read (standard columns pass) with a 403 PermissionError `APIError` (exit 5) before sending; when the meta is unreadable it proceeds, and `Aggregate` turns v15's answers into the same error (`checkColumns`: a missing column in the first row; `droppedColumn`: 1054 naming one of the aliases). ReadableFields does not count Desk User, so a level only Desk User reads is refused (safe side). `list-docs --fields 'count(name) as n'` therefore fails on v16 (documented, points to `ffc aggregate`). `runAggregate` takes the syntax from `serverInfo` (`client.SyntaxFor(major)`; unknown → dict) and on `client.SyntaxRejected` (status + exc_type only: the message is translated) retries once with the other; it drops the cache when the retry is accepted, and reports the retry's error unless the retry was refused as a syntax too. Field names are plain identifiers (`client.ValidIdentifier`, checked in buildAggregateQuery as usage errors and again in `AggregateQuery.validate`): no `link.field`/`child.field` (v15 cannot group by them, v16 would join a linked DocType the MCP policy never checked). Aliases are `count`, `sum_F`, `avg_F`, `min_F`, `max_F`; a clash with a group-by field is a usage error. ffc always sends `order_by` (default first aggregate desc; the group fields not in it are appended asc as tiebreakers) and sorts the rows itself (`sortAggregateRows`, `compareAggValues`: nulls first, numbers by value, strings case-insensitively), because v16 on PostgreSQL drops ORDER BY with GROUP BY (query.py:323-335) and the DB type is not cheaply knowable (get_versions has no db_type; System Health Report needs System Manager and runs every check). With a limit it asks for `max(limit+1, aggregateProbeRows=20)`; fewer rows than asked is every group; a full page out of order (`rowsSorted`, lenient about where nulls go) means the order was ignored, so it refetches with `aggregateFetchCap+1` (10000) and sets `Warning` (CLI stderr, MCP `warning`) when that cap was hit. Fake: `Site.Postgres()` ignores the order of grouped v16 queries. `count-docs --group-by` is `frappe.desk.listview.get_group_by_count` (GET; `doctype`, `current_filters` required, ffc sends `[]`, `field`; rows `{name, count}` renamed to `{FIELD, count}`, at most 50, `owner` puts the caller first, `assigned_to` counts per System User the ToDos not Cancelled (Closed included) whose `reference_name` is a matching name, reference_type not compared (listview.py:38-63), v16 adds `title` for Link fields with show_title_field_in_link; an unknown field is a bare 500 ValueError → exit 6). Fake: aggregates follow `SetApps`' frappe major (v16 rules from 16, v15 below, including an empty version), `get_group_by_count` mirrors the above; below 16 it also applies v15's group_by/order_by check (`v15CheckOrderGroup`: ORDER_GROUP_PATTERN and the operator words, 417 "Illegal SQL Query"), and a DocField whose permlevel (`Permlevel`) none of the `SetUser` roles reads in the `DocPerm` rows is refused on v16 (403) and dropped from fields on v15 (403 in group_by; ORDER BY a column that is neither a selected alias nor a field is 500 OperationalError 1054). The contract test `aggregates by version` pins both refusals per version, and its subtest `permission level` (own fixture DocType `FFC Contract Perm`, marker-checked teardown, the Desk User fixture user) pins the raw permlevel behaviour and exit 5 from ffc.

- **count-docs --at-least (T3.6).** `client.CountAtLeast` POSTs `frappe.desk.reportview.get_count` with `limit` (v16.36.1 reportview.py:60-101; the v15 branch counts the same LIMIT subquery, without a timeout): it counts a `LIMIT n` subquery, so the answer is min(total, n). v16 on MariaDB runs it under `max_statement_time=1` and answers null on a timeout (ok=false: the CLI prints `unknown` and a stderr warning and exits 0; MCP `count_docs` `at_least` keeps `warning` in the result). The answer is also capped at n client-side, since a virtual DocType's controller may ignore the limit. POST like GetCount, so a long `in` filter never meets a URL limit. Not with `--group-by` (usage error). Fake: `getCountLimit`; contract: `contractAggregate`.

- **Prepared reports (T3.6, `client.RunPreparedReport`, internal/client/prepared.go; `run-report --prepared/--fresh/--wait/--prepared-name`).** `RunReport` always sends `ignore_prepared_report=1` (live run in the request). Frappe v16.36.1: `query_report.run` without it answers, for a prepared report, the user's newest Completed Prepared Report with the same filters (`get_completed_prepared_report`: status, filters, owner, report_name) plus `prepared_report: true` and `doc`, or `doc: null`; `prepared_report_name` inside the filters picks one. A Prepared Report without its result file (failed job) is also `doc: null` (logged as "Prepared report render failed"). `make_prepared_report` is permission-checked through `get_report_doc` (Report `is_permitted` and report permission on ref_doctype), inserts with ignore_permissions and enqueues `generate_report` on the `long` queue (timeout the Report's or 25 min). `get_reports_in_queued_state(report_name, filters)` lists the user's Queued/Started ones and needs no role; reading a Prepared Report document needs System Manager or Prepared Report User, so it is only used for the error message. Filters are matched as `frappe.as_json` (sorted keys, no spaces), which encoding/json produces. Flow: run (permission check; a non-prepared report returns live), the completed result unless `--fresh`, else the queued job or a new one, poll the queued list (`PreparedPollStart` 1 s doubling to 5 s, bounded by `--wait`), then run with `prepared_report_name`. Pending/failed is `*client.PreparedReportError`, exit 7 (`preparedError`, with the resume command; a failed job's message is the last line of its traceback, `lastLine`). Every non-ignoring run sends `are_default_filters=0`: with the default (true) a Custom Report's saved `custom_filters` replace ours. `--prepared-name` is checked first (`checkPrepared`: another report or other filters is a StateError, exit 6, because run only checks the owner (v16 also the report) and the wait looks among our filters' jobs; skipped only on a 403, any other read error is returned). The final answer's `doc` (the Prepared Report, no read right needed) is always checked the same way (`matchPrepared`), so a skipped check cannot return another report's or other filters' result. MCP `run_report` `prepared`/`fresh`/`prepared_report` (`runPreparedMCP`, mcp_tools.go): waits at most `mcpPreparedWait` (1 min) with `sendProgress` (no total), a job still running is the result `{status: queued, prepared_report: {name}, hint}`, not an error; a read-only policy sets `ReuseOnly` (a finished result or a queued job only, else `client.ErrNoPreparedReport`; `fresh` refused), because make_prepared_report inserts a document and starts a job; the concise result adds `prepared_report: {name, finished}`. The Prepared Report reads (`checkPrepared`, the failure message) are not checked against the DocType rules: they only touch the user's own job's report name, filters, status and error. Fake: `AddReport` + `PrepareReport(name, polls, failure)` (polls < 0 = no worker; changing it affects queued jobs); contract: `contractPrepared` (a non-standard Query Report `FFC Contract Prepared` with prepared_report=1; pwd.yml has a queue-long worker).

- **Document context (T2.1).** `ffc doc-info` and MCP `get_doc_context` share `fetchDocContext`/`compactDocContext` (doc_info.go).
