# OAuth internals

Moved out of the root CLAUDE.md so it loads only when the work touches this area. Notes for contributors and AI agents; the root file keeps the rules that apply everywhere.

- **OAuth refresh** happens in `loadSite` (site_client.go), only for commands that talk to a site, under the config lock; it re-checks expiry after taking the lock so concurrent processes refresh once. Failures warn on stderr and the command proceeds (it then gets a 401). There is no refresh in `PersistentPreRunE` any more. **During a run** (T2.11), `newSiteClient` gives an OAuth client `tokenRefresher` (refreshOAuth with the rejected token: the stored token is taken when it differs, so a refresh by another process is reused). The access token is attached per request in `client.send`, not on the resty client. On a 401, `refreshToken` (single-flight under `loginSem`, a one-slot channel a waiter leaves when its ctx ends; keyed by the token the request used) first probes `frappe.auth.get_logged_user` with that token: only a 401 there means the token itself is refused (Frappe checks it in `validate_auth`, frappe/auth.py, before the method runs), so the request did not run and is repeated once, writes and `Raw` included (`Raw` bodies are `[]byte`, replayable). A 401 the method raised itself (token still valid) is returned, never retried; a write rejected while another request already refreshed probes its own token too (a read just retries). A failed refresh is returned as the 401 with a hint and remembered per token only when definitive (`permanentRefreshError`: token endpoint 400/401/403 (403 is Frappe's answer to a revoked refresh token), `ErrNoRefreshToken`, a refreshed token refused again by `refreshedRefused`, e.g. a disabled user); 5xx, network and lock errors are retried by the next request. The MCP server uses `newSiteClient` too; its cached client is rebuilt when the stored token changes. Fake: `ExpireToken`/`ExpireTokenAfter`, `FailRefresh`, `Refreshes`, `RefreshToken`/`OAuthClientID` (in `fakeConfig(…, "oauth")`); the real 401 and refresh are pinned by `TestContractOAuthExpiry` (contract_oauth_test.go).

- **OAuth registration and revocation (T3.7).** Frappe facts (v16.36.1 source; v15 branch checked on GitHub): the metadata is `GET /.well-known/oauth-authorization-server` (app.py:172 → `handle_wellknown`, oauth2.py:293), served only while OAuth Settings `show_auth_server_metadata` is set (default 1, oauth_settings.json), else NotFound; it carries `registration_endpoint` only while `enable_dynamic_client_registration` is set (default 1; oauth2.py:353). v15 has neither (no `handle_wellknown`, no `register_client`), so any non-200/non-JSON metadata means "no registration". `register_client` (oauth2.py:359, allow_guest POST, JSON body; NotFound when disabled) validates `OAuth2DynamicClientMetadata` (integrations/utils.py:17, pydantic: `redirect_uris` and `client_name` required) and `validate_dynamic_client_metadata` (utils.py:206: grant types ⊆ authorization_code/refresh_token, response types only `code`, outside developer mode https or an http loopback IP literal, any port; `localhost` is refused), then `create_new_oauth_client` (utils.py:241): app_name = client_name, scopes = `scope` or "all", `skip_authorization` 0 (the consent page shows), grant Authorization Code, `token_endpoint_auth_method` "None" for `none` (public, no secret in the 201 answer), owner Guest, allowed role Desk User (oauth_client.py:62; a website user cannot use it). No check for an existing client: every call creates one. v16.36.1 has no rate limit on it; Frappe's develop branch has `@rate_limit(limit=5, seconds=600)` per IP (429 RateLimitExceededError), which the hint names. Frappe stores redirect URIs joined by `\n` but `validate_redirect_uri`/`confirm_redirect_uri` split them on spaces (oauth.py:27-40, 170-179), so ffc registers exactly one URI (this run's port) and the scope `openid all` (a missing `openid` would fail `validate_scopes`, oauth.py:48). `sitesetup.ResolveOAuthApp` posts to the configured site URL with the endpoint's path (the issuer comes from the request URL, which can be http:// behind a TLS proxy) and refuses another host. `revoke_token` (oauth2.py:188, allow_guest POST, form body) runs oauthlib's RevocationEndpoint: `client_authentication_required` is not overridden (always true), so `authenticate_client` (oauth.py:93) loads the client from `client_id` in the body (no secret checked; without it, it looks up `token` as an access token name, which fails for a refresh token); the validator's `revoke_token` (oauth.py:263) sets the OAuth Bearer Token with that `refresh_token` (hint `refresh_token`) or that name (otherwise) to Revoked, which kills the access token of the same record too (a refresh with the revoked refresh token is then a 403 PermissionError, not invalid_grant: validate_refresh_token's get_doc raises DoesNotExistError, which `handle_does_not_exist_error`, permissions.py:926, turns into PermissionError for Guest; `permanentRefreshError` counts that 403 as definitive, so a long-running client stops refreshing; an unknown `client_id` is the same 403, from authenticate_client's get_doc, which revoke_token does not catch at oauth2.py:198; revoking by the access token revokes the record and so its refresh token too); the answer is `{}` with 200, also for an unknown token, or oauthlib's status (400 for a missing token: create_revocation_response catches its own InvalidRequestError). site remove therefore sends `token`, `token_type_hint=refresh_token` (access token when there is none), `client_id`, no Authorization header (an expired bearer would be refused by validate_auth first), before taking the config lock (`sitesetup.RevokeToken`), bounded by `revokeTimeout` (10 s, site.go), and only warns on failure. A refresh leaves the previous refresh token active (`save_bearer_token`, oauth.py:203, saves a new record with `new_doc` and never revokes the old one), so older refresh tokens of the same login are not revoked. Fake: `SetAuthServerMetadata`, `SetDynamicRegistration`, `FailRegistration(status)`, `Registrations()`, `Revoked()`, `AuthCode` (the token endpoint's authorization_code grant); cmd tests stub `openBrowserFn`, sitesetup tests pass `LoginHooks.OpenBrowser`. Contract: `TestContractOAuthRevoke`, `TestContractOAuthRegistration` (skips without registration).
